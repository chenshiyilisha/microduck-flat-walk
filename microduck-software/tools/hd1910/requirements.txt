# Deploy-verification toolchain dependencies (Pass12 + Pass13, 2026-11-08).
#
# These are the pip packages needed to RUN the deploy gate that lives in this
# directory:
#   - verify_policy_bundle.py  -> needs onnx (+ numpy for the numeric normaliser checks)
#   - rehearse_hd1910.py       -> needs onnx (reads runmeta/heading_meta to infer plant)
#   - verify_policy_inference.py -> needs onnxruntime (+ numpy) to EXECUTE the ONNX and
#                                  sanity-check its output (the "static-only" blind-spot
#                                  closer; SKIPs cleanly if these are absent)
#   - audit_robotd_toml.py     -> stdlib only (tomllib, Python >= 3.11)
#   - pre_deploy_check.py      -> stdlib only (shells out to the above via subprocess)
#   - record_provenance.py     -> stdlib only (reads companion runmeta/heading_meta + git)
#   - assert_ci_verdict.py     -> stdlib only (asserts a --json gate report is a real run)
#   - assert_clean_checkout.py -> stdlib only (probes which gate inputs this checkout has)
#   - tests/                   -> pytest, stdlib only (the tooling regression suite)
#
# WHY THIS FILE EXISTS: the repo's only dependency manifest was
# microduck-software/repo/pyproject.toml, which describes the TRAINING env
# (microduck-mjbatch: mujoco / torch / mjbatch) and does NOT declare onnx or
# onnxruntime. A fresh `git clone` + `uv sync` therefore could not re-run the
# bundle/rehearsal/inference gates, so the "deploy-ready" verdict was not
# reproducible. This file pins the verification toolchain separately from training.
#
# VERSION PINS mirror upstream pollen-robotics/microduck_rl's pyproject.toml
# (onnx>=1.20.1, onnxruntime>=1.24.4) so the verification env matches the project
# that produces these policies. numpy is needed by the inference/bundle numeric paths.
#
# INSTALL (from this directory):
#   python -m pip install -r requirements.txt
#   # or, with uv:
#   uv pip install -r requirements.txt
#
# NOTE (Pass16 correction, 2026-11-08): the Pass12/13 note that used to live here
# claimed "onnx / onnxruntime cannot be pip-installed in this sandbox". That was
# WRONG. It came from running the SYSTEM Python 3.13 instead of the project's own
# `.venv-mjlab/Scripts/python.exe` (Python 3.12.13), where torch 2.9.1+cu128,
# onnx 1.23.2, onnxruntime 1.31.0, numpy, scipy, mjlab_microduck, mujoco and
# pytest 9.1.1 are all already installed. "Cannot install" was "wrong
# interpreter" -- check for an existing venv before declaring a dependency absent.
#
# Also: this workflow DOES install onnxruntime, and assert_ci_verdict.py therefore
# requires the `inference` stage to be PASS. An inference SKIP in CI is a BROKEN
# GATE (Pass16 fixed exactly that), not a clean partial install. Do not
# reintroduce wording that treats it as an acceptable outcome.
#
# PASS18 BOUNDARY (2026-11-08): this is deliberately the LEAN verification
# toolchain. It does NOT install mjlab_microduck / torch / mujoco / scipy, which
# the `contract` conductor stage and the cfg/IMU regression tests need. In CI
# those are EXPLICIT SKIPs:
#   * pre_deploy_check.py --selftest-allow-skip contract.selftest -> PARTIAL
#   * assert_ci_verdict.py --allow-skip contract                  -> PASS*
#   * tests/test_hd1910_configs.py and the IMU-chain test skip with a reason
# `assert_clean_checkout.py --strict` asserts that every COMMITTED gate input
# (3 onnx + 9 upstream contract sources + companion meta) is present and
# byte-identical, so 4 of 5 conductor stages really execute in CI.
# Before shipping, run conductor + pytest locally with .venv-mjlab for 5/5.
onnx>=1.20.1
onnxruntime>=1.24.4
numpy
pytest>=8
