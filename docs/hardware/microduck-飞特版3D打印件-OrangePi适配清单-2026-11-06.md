# MicroDuck 飞特版 3D 打印件 × Orange Pi Zero 3W 适配清单

_2026-11-06。资料源：本地 `fanhao375/microduck-replica-cad`（飞特版 v2.2，BOM 2026-10-23，33 打印件 + 23 外购件）、官方 orangepi.cn 参数页、第三方评测（Orange Pi Zero 3W Review，blogarama 收录）。随 `docs/hardware/microduck-最优方案-价格硬件软件-2026-11-06.md` 与 `cad/orangepi_zero3w_carrier.scad` 一起看。_

## 0. 一句话结论

飞特版 v2.2 的 **33 个打印件里，31 件与主控板无关，可直接用**；真正随"换板"变的是**电气层（40-pin HAT 引脚）**，不是机械层。

> ⚠️ **2026-11-06 更正（重要）**：本节原稿写的"Orange Pi 孔距一致、仅 2mm 宽余量待核就能塞进 `trunk_base` 型腔"是**基于错的前提推的**，作废。
> 实际（见 README + 躯干主体图）：
> - `trunk_base_躯干底座` 的本职是**髋 yaw 舵机安装位**，**不是 SBC 卡位**；
> - SBC（Radxa/Pi）+ HAT + imu_to_dxl 那一套，是作为"**控制器**"装在 **`01 躯干主体`（torso 主壳）的型腔**里，不是某个按 Pi 板型挖的口袋；
> - 躯干图里那个蓝色小板是接口/转接 PCB（imu_to_dxl 或 HAT），**不是 SBC 本身**。
> 所以"换 Orange Pi 只需多 2mm"不成立——真正的机械约束是**躯干主壳控制器型腔能否容下 Radxa+HAT 整栈**，而 Orange Pi 既宽 2mm、40-pin 又不兼容 HAT。我之前建的 `cad/orangepi_zero3w_carrier.scad`（69×36、带耳 89mm 的外挂板）比裸板还大、且按"外挂耳板"思路建模，跟作者"整栈塞进躯干型腔"的做法对不上，其"适配"**未经实测、前提已错**，不能直接用。

> 顺带收口一个矛盾：作者 CAD 的板模型命名 `pcb__raspberry_pi_zero_2_w`，但仓库 README 第 357 行明说「实机主控是 **Radxa Zero 3W（RK3566）**，只是外形同为 Pi Zero」。也就是说 **fanhao375 这套事实标准机械件，本来就按 Radxa Zero 3W 建**——这跟你之前定的「最优方案 = Radxa Zero 3W + 官方 Apache-2.0 fork」完全对齐。你中途探索的 Orange Pi Zero 3W（A733）是另一条分支。

## 1. 先澄清：换的是什么"不兼容"

| 维度 | Radxa Zero 3W（作者实机） | Orange Pi Zero 3W（A733，你探索的） | 对 3D 图纸的影响 |
|---|---|---|---|
| 板型 | Pi Zero 2W 板型，65×30 mm | 65×32×1.2 mm（官方中文参数页；英文页有一处写成 30×65，以中文页为准） | **机械：孔距一致，仅宽 2mm** |
| 安装孔 | Pi Zero 2W 四孔位 | 第三方评测确认「Both boards share **identical hole spacing**」 | 作者的 Pi Zero 型腔孔距对得上 Orange Pi |
| 40-pin | RPi 兼容定义 | **≠ RPi 定义**（A733 的 40-pin 不是树莓派引脚） | **电气：树莓派机器人HAT 不能直插** |

**判定**：机械层低风险的依据是"孔距相同 + 开顶式卡框容得下 2mm 边余量"；**真正的不兼容在 40-pin 引脚**，这不影响打印件，但影响 BOM 第 3 项（树莓派机器人HAT电路板）能不能用。

## 2. 33 打印件逐类判定

判据口径：**"随主控板变" = 该件的几何取决于 SBC 板型 / 40-pin / HAT / 摄像头接口**。其余件无论换 Radxa 还是 Orange Pi 都不动。

| 类别 | 件（BOM 序号） | 是否随板变 | 判定 | 依据 |
|---|---|---|---|---|
| 头壳 / 面部 | 头部上壳(1)、头部下壳(2)、面部零件(3)、下巴(4)、软下巴(5)、软嘴顶部(6)、眼睛(7) | 部分 | **直接用**；仅 `face_part` 有 `-FT1` 适配瑞莎摄像头变体，摄像头若换型要核对孔距 | 外观件，不接触 SBC |
| 颈 | 颈部(8)、颈部俯仰(9) | 否 | **直接用** | 纯结构 |
| 躯干基准 | 躯干底座(10) | 否 | **直接用**；本职是**髋 yaw 舵机安装位**，与 SBC 无关（原稿误写为"SBC 卡位"，已更正） | 纯结构，不随板型重做 |
| 腿 / 髋 / 踝 / 脚 | 髋部左(13)、偏航转横滚(14)、偏航横滚运动(15)、腿部(16)、左上腿(17)、右上腿(18)、上腿加固板(19)、左脚(20)、右脚(21)、左脚底(22)、右脚底(23)、脚踝左(24)、脚踝右(25)、脚踝左V1(26)、脚踝右V1(27)、轴承滚轮(33) | 否 | **直接用**（已是飞特版舵盘配合件） | 纯舵机 / 结构 |
| 轮滑 / 转接 / 电池 | 合体轮胎(28)、滚轮叶片(29)、电机支架(30)、电源支架(31)、香蕉形PCB锁扣(32) | 否 | **直接用** | 跟电池 / 香蕉插头转接板 / 轮滑相关，与 SBC 无关 |
| 真正跟 SBC 机械相关 | （无独立 SBC 载板打印件） | — | 见 §1：SBC 由 `trunk_base` 型腔卡住，孔距一致故免改 | 33 件中**没有**"固定 SBC"的专属打印件 |

**汇总**：33 件 → **31 件直接用**；2 件（`banana_pcb_locker` 香蕉插头PCB锁扣、`power_support` 电源支架）跟 SBC 无关也直接用；唯一可能要动的只有 `trunk_base` 内 SBC 卡位的 2mm 宽度余量（且是"放宽"而非"重做"）。

## 3. 真正要解决的（不是图纸，是电气）

BOM 第 3 项「树莓派机器人HAT电路板」（¥120）按 RPi 40-pin 设计，**Orange Pi 的 40-pin 定义不同 → 不能直插**。三条出路：

| 选项 | 做法 | 代价 | 对 3D 影响 |
|---|---|---|---|
| **A（推荐，零机械改动）** | 主控板改用 **Radxa Zero 3W**，与作者 CAD 完全对齐，HAT 直插 | 放弃 A733 的 NPU/性能；但 50Hz 走路推理 RK3566 够用 | 无；33 件全直接用 |
| B | 保留 Orange Pi，重做 HAT 接口（引脚重映射 + IMU/ToF 改走其他接口） | 工作量在 PCB/固件，不在 3D | 无新增打印件 |
| C | 不插 HAT，用飞特 URT2 调试板 + 独立 `imu_to_dxl` 小板（BOM 第 4 项）绕开 40-pin | 需确认总线时序与 robotd 配置 | 无新增打印件 |

> 个人建议：若以"最大复用 fanhao375 机械件、少踩坑"为目标，**主板回到 Radxa Zero 3W** 是最省心的——作者的型腔、HAT、BOM 全部对得上，33 件零改动。Orange Pi 分支只在你明确要 A733 的 NPU 时才值得，那时用 `cad/orangepi_zero3w_carrier.scad` 兜住机械，但 HAT 必须走 B 或 C 另解。

## 4. 我已有的保险件（⚠️ 前提已错，不能直接用）

`cad/orangepi_zero3w_carrier.scad` / `cad/orangepi_zero3w_carrier.stl` —— 独立 SBC 外挂载板（参数化，OpenSCAD 源 + 纯 Python 生成的 STL）。

**更正**：这块板**不是**为"`trunk_base` 卡位放不下 32mm 板"兜底而建（那个前提错了）。它是按"外挂耳板（左右长圆孔 M3 拧到躯干外侧）"思路建的 69×36、带耳 89mm 的板，比裸 Orange Pi（65×32）还大，跟作者"把 Radxa+HAT 整栈塞进**躯干主壳型腔**"的实际做法对不上。其"适配"**未经实测、前提已错**：
- 在 **Radxa 路径**下它**完全不需要**（Radxa 整栈按作者设计直接进躯干型腔，33 件零改动）；
- 在 **Orange Pi 路径**下它也不能直接救场——Orange Pi（65×32，宽 2mm）要进的是同一个躯干控制器型腔，而我的外挂板比裸板更大、且 40-pin 不兼容 HAT 的问题它没解决。
它最多算一个"外挂固定 Orange Pi 到躯干外侧"的**起点草模**，要真用得上必须按真实躯干型腔/外壳螺接点重做尺寸与固定方式。

## 5. 仍需现场核的未知项（更正后）

- **`01 躯干主体` 控制器型腔的真实尺寸**（装 Radxa+HAT+imu_to_dxl 整栈的那个腔）：这是 Orange Pi（65×32）能否进去、以及我的外挂载板能否固定的**唯一真约束**。本地只有网格版 3MF，腔体尺寸无法直接量；需 418MB `SolidWorks-FT2026-10-20.zip` 源或实物。原稿误写的"`trunk_base` SBC 卡位"作废。
- Orange Pi Zero 3W 真实安装孔**数 / 孔径**（评测只确认"孔距一致"，待实物或官方机械图二次确认）。
- HAT 在 Orange Pi 上的可行性（电气，需 40-pin pinout 逐项对照）——这是 Orange Pi 分支真正的死穴，机械层再怎么凑都不解决它。
- 板角倒圆半径（官方未给，载板暂估 2.0）。
