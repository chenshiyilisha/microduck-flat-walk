## 0. 一句话结论

**BOM / 实物层：两版都能拼完整，57 项一件不少。几何层：拼不出精确整机——不是零件缺，是「整机装配位姿」这份数据不在可解析的资料里。本轮不造第二个假鸭子。**

- **Radxa Zero 3W 版**：33 项打印件 + 24 项外购件全部齐备，零改动；作者 2026-09-13 实机装成、**15 颗舵机全在位**，有实机背书。
- **Orange Pi Zero 3W 版**：打印件与 23 项外购件 100% 沿用，仅替换主控板 1 项，加 2 项软件配置差异；同样齐全，但**无复刻机身的实机背书**。
- 两版已各自产出可逐件点数的零件包与清单，见 §6。

## 3. 两版差异（只有 1 项硬件替换）

| 项 | Radxa Zero 3W | Orange Pi Zero 3W |
|---|---|---|
| 主控板（BOM 外购件 #1） | Radxa Zero 3W（RK3566），¥309 | Orange Pi Zero 3W（A733） |
| 33 项打印件 | 飞特版 v2.2 通用 | **完全相同** |
| 其余 23 项外购件 | 通用 | **完全相同** |
| HAT 40-pin | RPi 兼容 | **与 RPi 同脚位，可直插**（已核：UART 8/10、I2C 3/5、5V/3.3V、GND 全同） |
| 舵机总线 | 1 Mbps（`UART2_M0` / `ttyS2`） | **500 kbps**（A733 UART 分频限制，15 颗舵机 `reg6=1`） |
| 软件 | 系统默认 | 需开 `UART0`(Pin8/10) + `TWI0`(Pin3/5) overlay |
| 风险 | 低 | Pin27/28（HAT EEPROM I2C0）是否同脚位待核；A733 5V 轨带载需实测 |

两版 `kit_*.stl` 的**唯一几何差异**是主控板占位体宽度 30 vs 32 mm（Orange Pi 取官方中文参数页 65×32 的保守上限；多源写 65×30）——这 2 mm 正是「机械零改动」结论的几何体现。

## 4. 装配层级（来自 21 页说明书，两版通用）

```
01 躯干主体（整机基准，先固定）
├─ 02→06  左腿：左髋 → 左髋Roll → 左大腿 → 左小腿 → 左踝脚
├─ 07→10  颈头：颈根 → 颈俯仰 → 头Yaw/Roll → 头部总成
└─ 11→15  右腿：右髋 → 右髋Roll → 右大腿 → 右小腿 → 右踝脚（镜像）
```

说明书硬约束：装配前对照 BOM 清点零件与 M2/M2.5 紧固件；**舵机先通电归中位再锁紧**；螺丝对角分步预紧；左右对称件勿装反；每完成一个关节转动测试；首次通电前查极性/绝缘。

## 5. 为什么几何层「拼不出精确整机」

逐项排除，全部实测：

1. **3MF 零件网格**：33 个网格中心全 `(0,0,0)` → 只有局部几何，无装配位姿。
2. **3MF `<build>` 43 个 transform**：应用后 bbox `X[17,816] Y[-287,238] Z[-17,122]`，16 个实例 Z<0 → 是 Bambu 的**摊开陈列位姿**，既不是整机也不是可切片打印盘布局。
3. **`assembly_model.json`**：34 个组的 `assemble_transform` 平移 X=49…798 mm；`offset_to_assembly` **全部 `[0,0,0]`**；`assembly_step.json` 的 keyframes 全空 → 无整机位姿。
4. **417 MB SolidWorks 包**（本轮下载成功）：整机总装是 `00-microduck装配体-FT2026.9.23.SLDASM`（66 MB），**专有二进制**：非 OLE2、非 ZIP，全文搜不到 `xml` / `transform` / `Matrix` / `.SLDPRT` 等可读串；10 个 `.STEP` 全是**单件**局部坐标（AP203），无整机装配 STEP/STL。

→ 整机精确位姿只存在于需要 SolidWorks 才能打开的 `.SLDASM` 里。**本机无法还原，故不生成「看起来像鸭子」的假整机**；本轮只交付可验证的零件包。

若要真整机几何，只有三条路：① 用 SolidWorks 打开总装另存为整机 STEP/STL；② 找作者 MakerWorld 上的装配版 3MF；③ 实物三维扫描/逆向。
