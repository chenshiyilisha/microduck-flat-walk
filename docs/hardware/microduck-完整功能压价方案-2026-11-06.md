## 0. 一句话判决

**回到官方 zero3 基线：`Radxa ZERO 3W 2GB 带排针` + `kissqy R1 一键镜像` + `成品 HAT/IMU/HUB` + `1 Mbps 出厂总线`，复用已有的 PS5 手柄与 URT-2。**

理由不是「Radxa 更便宜」这么简单，而是：**完整功能的载体是软件栈，不是主控算力。**
官方 0.15.1 的七个守护进程（`robotd / configd / btd / padd / mediad / tofd / updaterd`）、
9 个策略、网页中控、蓝牙配网、手柄驱动、相机/ToF/音频、OTA 与声音身份，
kissqy R1 已经**整套移植到 HD-1910 并打包成一键镜像**；
而当前定案的 `A733 + B 代 robotd` 只覆盖运动控制，补齐全套应用层要自己写。

⚠️ **这不是推翻 `microduck-最优方案-价格硬件软件-2026-11-06.md`**：那份的目标函数是
「**最低价格换最强主控、软件自己写**」；本文的目标函数是「**不砍功能、压价**」。
目标函数不同 ⇒ 最优解不同。两份并存，按目标选，不互相覆盖。

## 1. 先定义「完整功能」：两个口径不能混

官方有两个硬件版本，功能表不一样。这一点必须先钉死，否则「不砍功能」无从判起。

| 项 | 零售版 `beta`（Seeed 定制板） | 官方开发版 `zero3`（**Radxa ZERO 3W**） |
|---|---|---|
| 主控 | RK3566 / 1 GB / 32 GB eMMC | RK3566 / 1 GB / 32 GB eMMC（Radxa 复刻用 2 GB + TF） |
| 相机 | GC2093 | IMX219，转 90° 安装 |
| ToF | 8×8，SPI | 8×8 VL53L5CX/L8CX，**I²C** |
| 身体 IMU | 总线 ID 200 | 总线 ID 200（**必需**） |
| 头部 IMU | LSM6DSV16X，**默认开** | BMI088，**默认关闭**、CPU 融合 |
| NFC | ST25R100 + 2 天线轮询 | **USB 读卡器，台架用，仅用于配对手柄** |
| 脸部 LED | 12 颗 | **无** |
| 音频 | TLV320AIC3104 + 麦 + 喇叭 | 同左，由 HAT 整合 |

**判据（一手）**：kissqy 的 `DUCK-SHOPPING-LIST.md` 就是 zero3 基线的完整 BOM，
里面**只有一块 IMU 板（ID 200），没有第二 IMU、没有 NFC、没有脸部 LED**。
⇒ 按 zero3 基线复刻，**不买这三样不算砍功能**，因为官方 zero3 本来就不启用。

**功能行为全部保留**：行走 / 坐下站起 / 蹲下 / 踢球 / 喙拾取 / 前滚翻 / 倒地起身 /
轮滑、手柄与网页/手机中控、热点配网、Wi-Fi/BLE、实时 3D 姿态与关节/IMU 反馈、
摄像头画面、ToF 避障与激光点跟随、叫声与嘴动作、OTA 与策略管理。

**唯一严格缺口**：零售版「NFC 标签识别物品」与脸部 LED 在 zero3 基线上不存在；
若坚持要，需补头 IMU + ST25R100 双天线 + LED（约 +¥100–200）**并自写驱动**，
且官方镜像按 zero3 编译时这些默认关闭。本文不复刻这两项，并明确记为差异而非遗漏。

## 4. 软件轴：换主控的真实代价与收益

### 4.1 收益（省的不止 ¥155 主控差价）

| 项 | A733 + B 代 robotd（当前） | Radxa + kissqy R1（本文） |
|---|---|---|
| 主控价 | ≈¥360（4 GB + eMMC） | ¥309（2 GB + TF，kissqy 实账） |
| 全功能软件栈 | ❌ 只有运动控制，App/相机/ToF/音频/OTA/中控要自己补 | ✅ 官方 0.15.1 整合镜像，一次刷卡完成 |
| 总线速率 | 500k，UART7 `/dev/ttyS7` | **1 Mbps**，出厂 reg6=0 |
| 15 颗 `reg6` | **必须逐颗 0→1**（方案 §4.3 已订正） | **一颗都不用写** |
| IMU 固件 | 必须重刷 `imu-feetech` 且**反转 PA1 DE 有效电平** | 成品已预烧 FT6、原生 1M，免改 |
| 设备树/引脚 | `aic3104-a733.dts`、40-pin UART7 | 镜像已按 Radxa 配好 |
| 编译 | 自己 `cargo build` | 免编译，刷镜像即起 |

### 4.2 代价（必须写清，别只报好消息）

1. **放弃 A733 专属软件资产**：B 代 robotd 的设备树、UART7/ttyS7 绑定、
   `out/robotd_hd1910_mode0.toml` 的引脚相关审计结论，在 Radxa 上不直接适用。
2. 🔴 **部署链变了**：kissqy 镜像用 **R17 V167 中控 + 自己的模型管理**，
   不是 B 代的 `uv run publish → robotctl policy load`。
   ⇒ 我们训的 **`p8head_2999`（`hd1910_kp8` plant）不能假定可直接加载**。
   两条路：① 用镜像配套现成模型（完整体验、零移植）；② 把导出/发布链移植过去（用户已接受「软件可自己改」）。
3. 🔴 **P/D 口径不能混**：本仓部署档是 **`kp_fw=8`**（G0 闸门 0.5 判 `reg50==8`，
   真机 `reg21/reg50=8` 已持久化）；而 kissqy V164/V167 部署合同写 **P=5 / D=0 / 转矩 1000**。
   走镜像路线时二者必居其一，**不能让两个写者各写各的**。这是配置对齐，不是换 plant。
4. **不重训**：§3.6 仍成立——换主控载板不进 MDP / obs / plant。
   但若因改用镜像配套模型而切换 plant 口径（kp8→kp5），那是**换 plant**，必须重判甚至重训。
5. **许可边界**：kissqy 原创部分「个人学习、研究、**非商业**」，购物清单首页明写
   「未授权任何商业组织」。官方 0.15.1 是 Apache-2.0，但**适配层不是** ⇒ 不可商用/转售。
6. **上板必查**：Radxa 这条线要求 **5 GHz Wi-Fi**（2.4 GHz 会与无线手柄抢频段导致断网/SSH 超时）；
   镜像 R1 出厂预装 control.40，需经中控升到 **control.43**，版本对不上中控会报。

## 5. PS5 手柄：能用，但有一条待验边界

- ✅ **配对原生支持**：官方 `pair-a-gamepad.md` 明列三种手柄进入配对模式的方法，
  DualSense 是「同时按 Create + PS 直到灯条闪」；机器人侧 `sudo robotctl pad pair` 自动搜索，
  `robotctl pad status` 确认。kissqy `OFFICIAL-GAMEPAD.zh-CN.md` 写明「**官方 padd 原样编译**」。
- ✅ **省 ¥89.91**（清单原配是盖世小鸡启明星2，Xbox 模式）。
- ⚠️ **待上板验收的映射**：官方配对文档明确，`input` 的 `Bus/Vendor/Product/Version`
  四元组决定 SDL / `gilrs` 的 **mapping GUID**，不同手柄的**轴与键编号不同**；
  kissqy 网页中控是「标准 Xbox evdev」。DualSense 走 `hid-playstation` 驱动、键位是
  PlayStation 布局 ⇒ **Start/Select/A/X/LB/RB 对应 Options/Create/×/□/L1/R1 需实测**，
  必要时补一条 gilrs 映射，或直接用 R17 网页手柄控制（网页输入是标准 Xbox evdev）。
  这是零成本的验证项，不是采购项。
- ⚠️ 手柄连的是**机器人蓝牙**，不是 PC；故 5 GHz Wi-Fi 那条约束同时生效。
