# Microduck 研究报告

> 调研时间：2026-10-23 · 对象：Hugging Face / Pollen Robotics 开源双足机器鸭
> 信息来源：官方 GitHub 仓库源码与文档、官网商品页、媒体报道、国内复刻仓库与实测账单

---

## 0. 结论先行

1. **它的价值不在硬件，在"把 sim2real 完整链路压到 399 美元"。** 15 个舵机 + 一块 RK3566 就能造，全世界的创客都能抄。真正稀缺的是：一个 800 g 双足机器人能做 RL 训练、策略热插拔、OTA 回滚的**整套工程规范**，而且是 Apache-2.0。
2. **它确实是"部分开源"，不是全开源。** 软件全开（Rust + Apache-2.0）；一块关键 PCB 开源（RPI Robot HAT）；但**机械没有可编辑 CAD**（只有 MJCF + 47 个 STL）、**`imu_to_dxl` 板没开源**。国内所有复刻都是靠反推 MJCF 运动学树做的。
3. **国内复刻的经济性很怪**：按原版 XL330 舵机复刻，成本 9700–11000 元，比买整机（约 2600–2900 元）贵近 4 倍。所以国内的复刻主线不是"抄它"，而是**"换掉 XL330"**——飞特 HD-1910 平替能把成本压到约 2900 元。
4. **如果你只是想研究具身智能**：不用买、不用复刻，`microduck_rl` 里的 MJCF 模型 + 训练栈可以纯软件跑通，这是这个项目性价比最高的入口。

## 1. 它是什么

Hugging Face 在 2025 年 4 月收购了法国机器人公司 Pollen Robotics（先出了桌面机器人 Reachy Mini），2026 年 8 月 27 日推出 Microduck 并开启预售。

| 项 | 参数 |
| :--- | :--- |
| 尺寸 / 重量 | 约 25 cm 高 / 800 g（复刻实测 737 g） |
| 自由度 | 15 个 Dynamixel XL330-M288-T，其中 **14 个受策略控制**（第 15 个是可选的嘴部夹爪） |
| 主控 | 瑞芯微 RK3566，1 GB RAM / 32 GB 存储，跑 50 Hz 控制回路 |
| 传感器 | 摄像头、ToF 深度（8×8 矩阵，VL53L8CX 级）、**两个 IMU**、麦克风 + 扬声器 |
| 交互 | 蓝牙手柄、手机 BLE、笔记本 ssh、WebRTC 远程 |
| 预置行为 | 7 个（走、坐站、踢球、叼取、轮滑、起身……） |
| 价格 | 399 美元（欧洲 €444 含税运），四色可选 |
| 软件许可 | Apache-2.0（整栈） |
| 机械模型许可 | **CC BY-SA-NC —— 非商业**（打印件不能拿去卖） |

值得注意的是它的产品定位：**不做语音对话**。官方说法是"把它当一个活物，而不是一个助手"——用肢体行为、姿态、叫声建立情感连接，绕开大模型对话容易逻辑错乱、人格不稳的问题。这个判断在国内 AI 玩具圈被反复拿来对比（国内主流是"对话交互"路线）。

## 2. 商业侧：为什么爆

- 开售 24 小时订单额 260 万美元（约 6500 台），峰值**每 4 秒卖出一台**；4 天预订破 1 万台，累计超 454 万美元。
- 官方目标 2 万台，首批 2026 年圣诞节前发货；新订单排期已延到 **4–6 个月**。
- 供应链被真实打穿：15 个 XL330 的需求量 ≈ ROBOTIS 去年全年伺服销量的 70%。1 GB 内存的成本占整机 10–15%。
- 连带效应：主控是国产瑞芯微 RK3566，A 股瑞芯微因此涨停，市值一度到 862 亿。

爆的原因不是技术炫技，是**价格锚点被砸穿了**：之前最便宜的能跑 RL 的双足平台是宇树 R1（约 6000 美元），实验室级动辄数万美元。399 美元的潜台词是"摔了扶起来就行，不用担心摔坏几十万的设备"。

## 3. 技术拆解

### 3.1 机器人端：7 个 daemon，一条 Unix socket

官方 README 直接说"This repo is the duck's brain"。Rust，无框架，单 workspace。

```
 gamepad   phone     laptop      peer        GitHub
   │BLE      │BLE      │ssh        │WebRTC     │https
   ▼         ▼         ▼           ▼           │
 padd      btd      robotctl     mediad        │
   └─────────┴─────────┴───────────┘            │
        JSON-RPC 2.0 over unix socket          │
   ┌──────────┬──────────┬──────────────┐      │
   ▼          ▼          ▼              │      │
 robotd    configd    updaterd ◄────────┴──────┘
 50Hz       wifi/      签名校验
 控制环     身份/      原子换版
 安全层     配对       健康门+回滚
   │
   ▼ Dynamixel 总线：15 舵机 + IMU
```

设计上有几个值得抄的决定：

| 决定 | 为什么 |
| :--- | :--- |
| **`robotd` 是唯一能碰电机的进程** | 15 舵机 + IMU 共享一条串口总线，50 Hz 控制环独占它。其它进程只能发"意图"，能不能执行由 `robotd` 里的安全层判定 |
| **`configd` / `updaterd` / `btd` 不依赖 `robotd`** | 这是"救砖路径"：控制环起不来的机器人，恰恰是最需要配网、升级、回滚的那台 |
| **发布是"换目录"而不是打补丁** | 整包落在 `/opt/robot/daemon/releases/<ver>/`，校验签名 → 切 `current` 软链 → 重启 → 问 `robotd` 健康吗 → 不健康自己把旧版放回去，还有 boot counter 兜底崩溃循环 |
| **客户端一律同一套 API** | 手柄、App、CLI、WebRTC 数据通道发的是一模一样的 JSON-RPC 调用，所以这个 API 不会悄悄烂掉 |
| **策略热插拔** | 走路 / 起身 / 杂技是不同 ONNX，共享 **61 维观测契约**，可以随时接管机器人 |

61 维观测 = 48 维本体感知 + 13 维指令块 `[twist(3), head_pose(4), body_pose(6)]`。不用某个槽位就补零，**绝不删槽位**——这是整个策略族能互换的前提。

### 3.2 训练端：mjlab (MuJoCo Warp) + PPO

`microduck_rl` 仓库，Apache-2.0，需要 CUDA GPU 和 `uv`：

```bash
uv run train Mjlab-Velocity-Flat-MicroDuck --env.scene.num-envs 4096   # 1-2h 出可用步态
uv run scripts/export.py Mjlab-Velocity-Flat-MicroDuck --wandb-run-path ...  # → ONNX
uv run scripts/infer_policy.py --walking out.onnx                     # CPU MuJoCo 上排练部署
```

没有 GPU 可以加 `--hf-jobs` 直接丢 Hugging Face Jobs 跑。

任务族覆盖 13+ 个：速度跟踪、跌倒自恢复、起立、坐站、低头叼取、踢球、前滚翻、轮滑（含 swizzle 滑法）、下坡滑行、轮上起身、原地快转。每个主任务还有一个 **`-Backlash-` 孪生版本**。

### 3.3 最值钱的部分：用真机换来的 sim2real 教训

`CLAUDE.md` 是这份代码库里最有信息量的文件——它逐条记录了"为什么这么写"，因为每破坏一条，都会产出"在 viewer 里完美、上真机就废"的策略。摘几条：

- **执行器必须建模到电压控制律，不能用理想 PD。** 他们用 BAM 的 M6 模型仿真 XL330（反电动势、库仑/Stribeck/负载相关摩擦、电池电压跌落、指令延迟、摩擦随机化）。理由很直接：**在这个尺度上（几百克的机体 + 微型舵机），执行器保真度就是 sim2real gap 的大部分**。
- **齿隙（backlash）要单独建模。** 每个舵机串一个 ±1° 的被动铰链，而且因为真机编码器在齿隙的输出侧，观测和固件里的 PD 仿真都要"穿过"齿隙去读（`qpos[servo] + qpos[backlash]`）。
- **域随机化不能在 reset 之间累积。** 曾经有一个会累积的质心随机化器，"degrade 了每一次长训练，持续了好几个月"。
- **观测归一化必须烘进 ONNX。** 在仿真里 play 会自动再归一化一次，所以这个 bug 在仿真里是隐形的——只能靠强制走 `export.py` 规避。
- **策略不滤波**（no action low-pass）。训练有滤波 / 部署没滤波（任一方向）都会破坏迁移。
- **先在仿真里验证物理假设，再训练**：目标姿态必须是稳定平衡点；站立高度要从仿真里当前模型的实际躯干高度量出来——曾经有一个 5 mm 错的 `STAND_Z`，让目标变成不可达，白跑好几天。
- **先跑 5 迭代 / 64 envs 的冒烟测试再开长训练**，"花几美分就能抓住 95% 的配置错误"。

这类东西你在任何论文里都看不到，只有真做过 sim2real 的团队才会写在仓库根目录。

## 4. 开源边界：到底开了什么

| 项目 | 状态 | 说明 |
| :--- | :--- | :--- |
| 整栈软件 | ✅ Apache-2.0 | Rust daemon 全开，含 OTA 更新器 |
| RL 训练栈 | ✅ Apache-2.0 | mjlab + PPO + 13 个任务 + BAM 执行器模型 |
| RPI Robot HAT | ✅ 开源 | `pollen-robotics/elec_RPI_Robot_HAT`：KiCad 9 工程、Gerber、BOM、贴片坐标、STEP |
| MJCF 仿真模型 + 47 个 STL | ✅ 公开 | 含完整运动学树，零件相对位置精确到 0.1 mm、质量与惯量张量 |
| **可编辑机械 CAD / 装配文档 / 硬件 BOM** | ❌ 无 | 国内复刻全靠从 MJCF 反推 |
| **`imu_to_dxl` 板** | ❌ 未开源 | 全网无公开工程，目前只有国内逆向重建 |
| 机械模型许可 | ⚠️ CC BY-SA-NC | **非商业**。软件许可是 Apache-2.0，但不能覆盖模型的商业使用 |

这点很关键：**"开源硬件"和"能抄的硬件"不是一回事。** 官方给的是"能跑起来的知识"，不是"能开工厂的图纸"。

## 5. 国内复刻：四条路线，实际账单

这是目前最有意思的部分。核心矛盾：**XL330 在国内的零售价，让"复刻"比"买整机"更贵。**

国内 XL330-M288-T 报价离散度极大：正常渠道约 ¥250–350/个，但现货溢价能到 ¥500–780/个（媒体观测到 498–780 的区间）。按 15 个算，光电机就是 **¥3,750 到 ¥11,700**。而整机 399 美元 ≈ ¥2,600–2,900。

于是分成了四档：

| 档位 | 方案 | 成本 | 代价 |
| :--- | :--- | :--- | :--- |
| **原版舵机档** | XL330 ×15 + 树莓派 + 开源 HAT | **¥9,700–11,000**（按现货溢价）<br>¥4,000–5,000（按正常渠道） | 唯一能直接跑官方策略 + 官方训练链路；贵 |
| **正经复刻档** | 飞特 HD-1910 平替 ×15（¥118/个，力矩约 2.5 倍） | **≈ ¥2,880–3,000** | 总线协议不同要改协议模块，策略要按新舵机**重训** |
| **极限挑战档** | 小智 AI 方案 / 预告的"小黄鸭 lite" | **¥300–500** | 能动、能玩，但基本告别 RL 链路 |
| **捡垃圾档** | 二手优必选 Alpha 机器人拆机（16 舵机 + 铝骨架，¥200） | **¥200** | 舵机大 7 g、总线协议不支持自定义 PD，要自己换驱动 + 标定 |

关键时间线（都是 2026 年 8 月底到 9 月的事）：

- GitHub 上 `fanhao375/microduck-replica`（1.2k★）从 MJCF 反推出装配图 + 可编辑 SolidWorks 装配体 + 21 页装配说明书，配 B 站 8 集装机教程。
- `LuwuDynamics/xgoduck_hardware`（937★）走"重新设计电路"路线，用飞特 HD-1910，主控板 228–333 元，整机 2000 多元。
- `7757/fanduck`（"超能花钱鸭"，67★）**已实机复刻成功**，把物料清单、打印件、板件制造资料、3D 姿态镜像工作台全部打包开源（含 SHA256 校验）。
- `AI-FanGe/Microduck-build-tutorial`（1.35k★）走了另一条路：**用树莓派 Zero 2 W + ROBOTIS OpenRB-150 替代 RK3566 + 定制 HAT**，直接提供预构建系统镜像和 ONNX 行走模型——这条对"想快速跑通"的人最省事。

### 复刻的坑（来自实测复盘）

1. **舵机价格是决策核心**，不是技术。电机 4000+ 直接劝退是评论区最常见的话。
2. **官方液压/电压设计超压**：XL330 额定 6 V，原机实跑 6.6–8.2 V，超压约 37%。换飞特时它额定 4–8.4 V，满电 8.4 V 顶格。
3. **飞特舵盘配合件不能和 XL330 版混用**，打印件必须选对版本。
4. **`imu_to_dxl` 那块板没有公开工程**，得自己建或找社区逆向。
5. **总线 50 Hz 达不到就是白干**：有社区实测约 46.87 Hz（3000 轮窗口无漏读），差一点就得调总线时序。

## 6. 生态：不止一只鸭子

官方组织在鸭子周围铺了一整套，这块被大多数人忽略了：

| 仓库 | 是什么 |
| :--- | :--- |
| `microduck-arena` + `microduck-challenges` | **在线竞技场 + 挑战赛**。四个赛道：2 米冲刺、爬 1.5 米坡、轮滑冲刺、"达人秀"（才艺表演，观众投票）。策略在服务端固定赛道、5 个扰动种子、全速度扫频评测，时可信 |
| `microduck_emotions` | **14 种情绪原型**：每种情绪 = 一段动作 + 一段配套声音，一起设计。有 `quack.py` 用 numpy 合成鸭叫，还有手柄触发表情 patch |
| `microduck-gst-plugins` | RK3566 的 MPP 硬件解码 GStreamer 插件（aarch64 预编译） |
| `microduck_yocto` | 鸭子自己的 Yocto OS 构建 |

`microduck-arena` 有个细节挺硬核：**本地跑和服务器跑给出不同成绩**，因为"舵机模型足够混沌，仿真跑几秒后就发散了"，所以本地成绩只能算参考。这句自嘲式的诚实，比任何 benchmark 都说明他们真在搞仿真。

"达人秀"赛道还能做**群鸭表演**：一场物理仿真里最多 8 只鸭子，各有自己的策略、位置、关键帧和嗓音。

## 7. 判断与建议

**它是不是个真东西？** 是。159 行的架构文档、61 维观测契约、带齿隙的 ONNX 导出、会用 boot counter 兜底的更新器——这不是营销物料，是真上过产线的工程。

**该不该买？**
- 想学具身智能 / RL → **先别买**。clone `microduck_rl`，MJCF 模型 + 训练栈纯软件就能把整条链路跑通，一分钱不花。跑通之后你才知道自己缺的是钱还是 GPU。
- 想要个能摆在桌上的活物 → 399 美元是合理的，但排期 4–6 个月，实际到手可能到 2027 年初。
- 想复刻 → 中国玩家最优解是**飞特 HD-1910 路线**（约 2900 元），但必须接受"重训策略"。原版舵机复刻在现价下没有经济性。
- 想拿它做商业产品 → 注意机械模型是 **CC BY-SA-NC**，不能商用。

**它真正的历史位置**：不是"最可爱的机器人"，而是**第一个把"仿真训练→真机部署"的完整工具链做成 399 美元消费品的项目**。它把"我能不能训一个新动作"从"读三年论文"变成"跑两小时脚本"。
