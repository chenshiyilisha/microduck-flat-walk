# Part A · 8 毫秒里发生了什么

## 1. 策略不是"一个"，是一个调度系统

`policy.rs` 开头的注释把规则说清楚了：

> 走路和站立按**速度指令的大小**选择，跟 `microduck_runtime` 完全一样；技能网络——坐↔站、地面叼取、两个踢腿——由 `robotd` 里的**调度器显式选择**，优先级规则归它管。
> 每个网络共享同一个 61 维观测布局，所以一个技能 = 一次会话选择 + 一段指令块编码。LSTM 导出额外传 hidden/cell state，由各网络自己持有；传感器观测和关节动作不变。

翻译成人话：**没有"一个大模型管所有"，是一堆小网络 + 一套优先级调度。** 走路的门限是一个常数（低于它站立策略接管）。

## 2. 验证放在加载时，不放在推理时

这是整段代码里我最认同的一句设计：

> **一切在加载时验证，不在推理时验证。** 观测宽度错、动作数错、缺 ONNX Runtime 的 bundle，必须在**机器人还站着不动**的时候失败，并且能告诉调用方为什么——而不是六十拍之后、正在迈步的中间。
> `robotd` 把加载失败变成"保持姿势 + 上报不健康"，于是更新器会回滚这个版本，而不是留下一个走不动的机器人。

60 拍 = 60 × 8 ms ≈ 0.5 秒。**在迈步中途发现模型不对**，机器人已经摔了。

## 3. ONNX Runtime 的两个坑，都是真机上撞出来的

### 坑一：缺库时不报错，而是 panic

> 这个函数存在，是因为 `ort` 在库缺失时**不返回错误**——它在 `setup_api` 里 `expect`，而那条路径是懒加载的，任何 API 调用都可能触达。所以缺库会**中止碰它的那个线程**。
> 在控制环里，这意味着线程死了、一拍也落不下来，`robot.health` 永远回"循环还没完成一个周期"：**守护进程看起来是卡住，而不是在说 ONNX Runtime 没装。**

于是他们先探测库能不能加载，把"缺库"变成普通错误，附带操作员的修复方法。

### 坑二：探测通过了，照样 panic

注释里紧接着自己打脸：

> 它**不**意味着 `ort` 之后不会 panic，而这个注释的早期版本声称过不会。**一块跑 ONNX Runtime 1.20.1 的板子证伪了它**：库加载成功，探测通过，`ort` 在 `setup_api` 里的版本检查上 panic（`expected version >= '1.23.x', but got '1.20.1'`）。探测只能证明文件能加载，仅此而已。

所以有了 `catching_ort_panics`：把 `ort` 调用包起来，把 panic 转成 `PolicyError`。

为什么这么较真：

> 在控制线程里，**panic 比错误更糟**：线程死了，一拍也落不下来，`robot.health` 回一句"循环还没完成一个周期"——**唯一一句不指向任何病因的话**——而守护进程还好端端地服务着 socket。更新器于是为一个没人能处理的理由回滚了版本。

还有个细节：`AssertUnwindSafe` 是因为 `Session` 不是 `UnwindSafe`，作者专门论证了在这里是安全的（catch 之后不观察任何自己的状态，成功就 move 进 `Policy`，失败就 drop）。

## 4. 推理线程数：故意只用 1

> 一，故意的。原型用两个，但**在四核 A55 上控制线程会被一个它不拥有的线程池阻塞**；而对这么小的网络，线程池在同步上的开销大于它在并行上挣回来的。值得在真板上重新测量，而不是信任何一个数。

这条对任何想在嵌入式上跑策略的人都成立：**并行推理在小网络上经常是负收益，而且会抢控制环的核。**

## 5. 安全层：三道限位 + 一套日志哲学

`safety.rs`（937 行，比策略文件还长）定义了三种独立的限位，各有独立计数器：

| 限位 | 含义 |
| :--- | :--- |
| 非有限值 | 目标里出现 `NaN` / `Inf` |
| 行程 | 超出 XL330 的位置范围 |
| deadman（看门狗） | 上游不再发指令 |

**日志节流的设计值得单独拎出来**：

> 第一次触发**总是**上报——一个只夹一次的钳位是新闻，而在这之前这些根本不可见。之后每五十次一行：50 Hz 下就是每秒一行，能看出故障还在持续，又不会把 journal 写爆。跟 `robotd` 里总线读取告警同样的形状：第一次失败必报，之后每第十次。

**为什么是三个计数器而不是一个**：

> 三个限位是独立事件：一个 deadman 触发了一秒，说明不了有没有关节在被钳位；一个共用的计数器会让触发最多的那个把另外两个饿死（它们永远轮不到说话）。

**计数器清零的语义**：

> 每个计数器被"到达该检查且没触发"的 tick 清零，所以那个数字读作"**这情况持续了多久**"——这才是值得说、而且读者必须能跟"总共发生过多少次"区分开的数。

**一个刻意的例外**：

> 被判定非有限值的 tick 会在钳位检查之前就返回，所以它让行程计数器保持原状而不是清零。这是故意的，反过来更糟：一个在 `NaN` 和越界之间来回跳的目标，会每隔一拍就结束一次行程计数，然后两个限位每拍都报——正是这个计数机制要防的"每拍一行"。

## 6. 最难得的一点：它承认自己保护不了什么

```
/// XL330 的位置范围：一整圈，居中，从 count↔弧度换算而来。
/// 这是【执行器】的行程，不是逐关节的解剖学限位——alpha 机器人真实的关节限位在
/// MJCF 里，而 MJCF 没有 vendored 到这个仓库。所以这能抓住策略吐出 NaN、
/// 荒谬的动作尺度、或者垃圾张量；它【不会】阻止一个关节被驱动到机械上不明智的地方。
/// 如实记录，不粉饰——因为一个看起来像逐关节限位、其实不是的限位，
/// 会暗示一种没人真正拥有的保护。
```

这段注释的价值高于它保护的任何一行代码。

# Part B · 14 种情绪：动作和声音是同一个设计

## 1. 格式极简：10 Hz，13 个字段

`keyframes/<name>.json`，`step_s = 0.1`（每 100 ms 一个采样），所有数值都是**相对 home 姿态的增量**，弧度制，缺失字段按 0 处理。

| 字段 | 含义 |
| :--- | :--- |
| `neck` / `head_pitch` / `head_yaw` / `head_roll` | 头部增量；`head_pitch > 0` = 喙朝下，`head_yaw > 0` = 转向鸭子自己的左边 |
| `body_pitch` / `body_z` | 身体：`> 0` = 鞠躬，`< 0` = 蹲下 |
| `skill` | 鸭子坐下时为 `"sit"`（用于 devastated、play dead） |
| `mouth` | 喙的开合 0–1，**已经与声音同步好了** |
| `twist[3]` | 速度指令（x, y, 偏航） |
| `soften` / `relax` | 柔化 / 松弛（过渡用） |

**关键设计：`mouth` 是预先对好声音的。** 播放时不需要运行时做音画对齐——设计阶段就对齐完了。

## 2. 把 "laugh" 拆开看

3.0 秒，30 帧。逐帧数据（`head_yaw` / `head_pitch` / `body_pitch` / `mouth`）：

| t | yaw | pitch | body | mouth | 发生了什么 |
| --- | --- | --- | --- | --- | --- |
| 0.0–0.4 | 0 → +0.432 | 0 → −0.700 | 0 → +0.085 | 0 | 抬头（负 pitch = 喙上抬）、头甩向左侧、身体后仰 |
| 0.5 | +0.295 | −0.700 | +0.015 | **0.881** | 第一个 "haaa" 起 |
| 0.6 | +0.064 | −0.700 | 0 | **1.000** | 嘴张到最大 |
| 0.7–0.9 | −0.187 → −0.450 | −0.700 | 0.025 → 0.100 | 0.787 → 0.085 | 长音衰减中，头摆到右侧极限 |
| 1.1 / 1.3 / 1.5 | 往复 | −0.700 | 0.100 | **1.000 / 1.000 / 1.000** | 三个短 "ha" |
| 1.7 / 2.0 / 2.2 / 2.5 | 往复 | −0.700 | 0.05–0.09 | 0.865 / 0.668 / 0.603 / 0.493 | 后四个 "ha"，**幅度递减** |
| 2.6–2.9 | 0 | −0.597 → 0 | 0 | 0 | 收尾，头回正 |

对应 `emotions.json` 里的描述：

> 「喙朝上，每一声 'ha' 都让头摇一下、身体沉一下：先一声长的 'haaa'，然后七声短的，渐渐消失。」

**数据结构完全对得上文案。** 而且注意两个细节：

- `head_yaw` 在 **±0.45 rad（±26°）** 之间往复摆动，`body_pitch` 在每声 "ha" 上 **+0.05 ~ +0.10** 地沉一下——"晃头 + 身体随节奏起伏"是分别写在两个通道里的。
- 后半段 `mouth` 的峰值从 1.0 一路降到 0.49——**音量衰减不是靠音频的淡出，是写进动作里的**。

## 3. `robot_note`：动作设计必须服从平衡

`sad`（7.5 秒）的条目里有一句：

> **故意只做一半深度**：更深的低垂会把头部的质量往前移，真鸭子会往前走一步来稳住自己。

这就是"给真机器人设计动作"和"给动画角色设计动作"最本质的区别。同一个仓库里，`devastated` 则需要 `skill: "sit"`——因为要表达的幅度已经超出站立平衡能力，**只能先坐下**。

**表达幅度被物理约束直接砍。** 而且这个砍法是写在数据里的，不是写在文档里的。

## 4. 声音：一个种子就是一个嗓音身份

`quack.py` 是机器人 Rust 声音合成器的**精确 Python 移植**，为了"在 Mac 上用跟机器人完全相同的鸭子身份设计情绪音效"。三个关键点：

### 4.1 RNG 精确移植

```python
"""Personality traits (pitch centre, timbre, quackiness...) are derived with
an exact port of the Rust RNG (splitmix64 + xoshiro256++), so
`Personality(4145077059)` is this robot's voice."""
```

`ROBOT_SEED = 4145077059`。**这个数就是这台鸭子的嗓音身份**——音高中心、音色、"鸭味"程度全部从它派生。同一颗种子在任何机器上生成同一个人格。

（逐样本的噪声——抖动、气息——用的是 numpy 的 RNG、由那条流播种，所以"同一个角色，但不是逐比特相同"。）

### 4.2 设计 API 只有三个概念

```python
p = Personality(4145077059)
sig = quack(p, dur=1.0, contour=[(0.0, 300), (0.3, 250), (1.0, 120)],
            env=("expdecay", 0.02, 0.6))
```

- **`contour`**：`(时间, 频率)` 点列表，分段线性——就是"音调怎么滑"
- **`env`**：`("expdecay", attack, decay)` 或 `("bell", attack, release)`
- **`mods`**：单次覆盖人格字段，比如 `{"quackiness": 1.0, "am_rate_hz": 25.0}` 得到一个低吼

采样率 48 kHz（调音用 22.05 kHz）。

### 4.3 情绪描述里的声音，都是音乐术语

翻回 `emotions.json` 的文案，你会发现声音描述精确到音程：

| 情绪 | 声音描述 |
| :--- | :--- |
| `yes` | 一次清楚的点头，配一声**下滑三个半音**的 quack |
| `no` | 一次摇头，配两音节的 "no-ah"，**三种发声法**随机选一个 |
| `laugh` | 一声长的 "haaa"，然后七声短的 |
| `excited` | 一串**上行**的 quack |
| `devastated` | 坐下时的惊叫，**延后 0.3 秒**播 |

`devastated` 是唯一 `sound_at_s != 0` 的——因为"先坐下，然后才反应过来"这件事，必须靠声音延迟 300 ms 表达。

## 5. 播放路径：一个 patch

`robot/pad-expressions.patch` 是运行时的一段改动，作用在 `microduck` 主仓的某个 commit 上，让你能用手柄按出来：

- 按 **D-pad Up** 进情绪模式
- **短按** < 0.6 s
- **长按** = 按住 0.6 s 触发

每个情绪绑了具体按键（`sad` 是 A 短按，`laugh` 是 L3 短按……）。

# 两条线的交点

Part A 和 Part B 看似在做两件事，其实共享同一套世界观：

| | 控制环 | 情绪设计 |
| :--- | :--- | :--- |
| 硬约束是什么 | 8 ms 一拍，四核 A55 | 800 g 的平衡极限 |
| 约束怎么体现 | 推理线程只能 1 个；限位必须在加载时验 | 悲伤只能垂一半；暴怒必须先坐下 |
| 失败怎么记录 | 三道限位 + 每次触发都进 journal | `robot_note` 直接写在 JSON 里 |
| 不装懂 | 「这不是解剖限位，别以为有人保护你」 | 「深一点它就会往前走一步」 |

**这也是我最想从这份代码里带走的东西**：它对自己能力的边界说得非常清楚，而且把边界写在了**数据结构和注释**里，不是写在宣传页上。

一个 399 美元的消费级产品，愿意在源码里承认"这个限位其实保护不了什么"——这在硬件行业里相当罕见。
