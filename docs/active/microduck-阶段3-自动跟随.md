## 2. 三层拆分

```
┌─ 感知 ── 相机 → 目标方位 θ + 距离 d        ← 新增，唯一要新建的部分
├─ 决策 ── θ,d → (vx, vy, ωz)               ← P 控制器即可，或用 RL
└─ 执行 ── (vx, vy, ωz) → 14 维关节指令      ← 已有 walk 策略，冻结
```

**执行层现成的证据**：命令空间本身就是 `lin_x ±0.4, lin_y ±0.3, ang_z ±1.0`
（`docs/reference/microduck-上游真实配置对照.md:108`）—— 前进、横移、转向三件套正好是跟随所需的全部自由度。
且 `rel_turn_in_place_envs: 0.15`（同表 :106）说明 15% 的环境专门练过原地转。

**决策层为什么不用 RL**：跟随是"感知 + P 控制"的线性问题。

```
ωz = k_ω · bearing_err        # 方位误差直接给角速度
vx = k_v · clip(d − d_target, 0, v_max)
vy = 0（或侧向修正）
```

**决定性理由是调试性**：P 控制撞了我知道为什么撞（增益太大 / 目标丢失 / 距离饱和）；
换成端到端 RL，撞了我只能重训。RL 值得上的场景是"复杂地形 + 拥挤人群 + 跟随"联合优化——
那是 parkour 级工作量，不是这台鸭子现在该做的事。

## 3. ⚠️ 拦路虎：命令每 3–8 秒才换一次

这是查上游配置查出来的，之前整个项目都没注意：

```
resampling_time_range: [3.0, 8.0] s        ← 上游真实值
```

**而我们的评估器把这个时间常数抹掉了。** `freeze_command()`
（`tools/flat_walk/eval_velocity_in_sim.py:118`）：

```python
cmd.resampling_time_range = (duration, duration)   # 窗口 = 整段
```

⇒ **我们手上所有评测数据，全部是在"命令恒定"条件下取得的。**

### 由此得到一条硬判据

> **现有策略支不支持高频变化的命令，我们一条证据都没有。**

跟随要以 50 Hz 改指令，比训练分布快 **150–400 倍**，是典型的分布外（OOD）。
可能跟得上，也可能抖成一团——**目前无法预测，只能测**。

这条要当成纪律记住：**冻结一个配置域时必须回读生效值**（我们已经在 `rel_standing_envs`
上栽过一次同样的跟头，`eval_velocity_in_sim.py:120-129` 有现场记录）。

## 4. 必须先做的那个实验（半天，纯评估，零训练）

**在决定"训不训"之前，先把未知变成已知。**

### 协议

1. 用现有 `eval_velocity_in_sim.py` 改一个 `eval_tracking.py`：**不要** `freeze_command()`
2. 命令按**正弦**与**阶跃**两种波形，扫周期 **0.5 / 1 / 2 / 5 s**
3. 每个周期测：
   - `vx` 对 `lin_x` 的跟踪误差（RMSE + 相位滞后）
   - `ωz` 对 `ang_z` 的跟踪误差（同上）
   - **附加代价**：同期 reward 惩罚项（`action_rate` 等）比恒定命令高多少
4.  checkpoint 用 `walk_std004_1250`（当前交付点）
5. 本地 4070 即可，**不需要新 REFERENCE_MODEL，也不需要买硬件**

### 判据

| 结果 | 对策 |
|---|---|
| 1–2 s 周期仍跟得住 | **什么都不用改。** 现有策略直接跑跟随。最好结果 |
| 只有 5 s 以上能跟 | 改 `resampling_time_range` 到 `[0.1, 0.5] s` 重训低层 ⚠️ 属 **domain 改动**，按我们的纪律必须从零重训，不能接着训 |
| 完全不行 | 高层只能降频到 3–8 s 发一次指令 ⇒ 一顿一顿。配 **0.15 m/s 速度地板**（`walk_std004` 的低速死区），一个指令周期要走 0.45–1.2 m，**必过冲**。这条基本是死路 |

**第三步若是唯一出路，则应放弃跟随，转做定点微调/遥控——这本身也是一个可接受的结果，且提前半天就能知道。**

## 5. 如果最后真要训：分层训

不要端到端。**冻结低层，只训高层。**

| 维度 | 值 |
|---|---|
| 动作空间 | **3 维**（vx, vy, ωz），不是 14 维 |
| 低层 | 冻结 `walk_std004_1250`，当确定性执行器 |
| Episode 长度 | 短（10–20 s 足够） |
| 采样效率 | 极高（3 维动作 + 低层冻结 + 短 episode） |
| 成本估计 | 本地几百 iterations 出东西，**比端到端视觉策略便宜两个数量级** |

观测侧把感知结果做成抽象量（`bearing_err`、`d`、`d_target`），**不要喂图像**——
喂图像就把自己和 Checklist 里的 domain randomization 绑死了。

## 6. 感知选型（这块反而最简单）

| 方案 | 判定 | 说明 |
|---|---|---|
| **AprilTag / ArUco 标签** | ✅ **首选** | Radxa ZERO 3W 的 CPU + OpenCV 就跑得动；一次同时给距离与方位；鲁棒性可调；标签打印几分钱 |
| 轻量人形检测（NPU 0.8 TOPS） | 次选 | 只给框，深度要另外算；遮挡难处理；帧率未知 |
| VL53L8CX ToF | ⛔ **不够做跟随** | 量程约 1 m（**待实测复核**），够做避障，人稍微走远就丢目标 |
| UWB / 蓝牙 AoA 信标 | 备用 | 最稳、不依赖视觉，但贵，且目标身上要带东西 |

### 隐藏优势：主动稳头不需要 RL

头部有 **5 颗舵机（ID 30–34）**，可以用头部 IMU 反馈驱动伺服做反向补偿，抵消步态抖动带来的画面晃动。
这对上层感知（尤其帧间差分/检测）是白捡的收益，而且是**纯控制问题**，跟 RL 无关。
