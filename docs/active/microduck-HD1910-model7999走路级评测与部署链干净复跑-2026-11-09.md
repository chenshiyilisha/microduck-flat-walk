### 3.1 判决（双轴，不许只看 vx）

1. ✅ **7999 达到走路级**：`no_fall` / `stays_upright` / `translates_forward` /
   `feet_clear_8mm` / `steps_alternate` 在 kp8 与 default 全部 PASS，4 个 seed 零终止。
   它同时把 `error_vel_xy_le_0.25` 从 2999 的稳定 FAIL 翻成稳定 PASS，速度 +14%。
   ⇒ **续训不是白跑，bundle 装 7999 有物理依据**（此前只有训练指标 mean_reward 98.63）。
2. 🔴 **但不能宣布「全面替代 2999」**：`not_sideways` 在 7999 的 4 次 kp8 里 **3 FAIL / 1 擦边 PASS**
   （`|dy|/dx` ≈ 0.50–0.58，阈值 0.5），而 2999 两次与 default 一次**全 PASS**（≈0.29–0.36）。
   侧向漂移与 `wz`、yaw drift 同步变大（7999 首跑 wz +0.122 / yaw 8.6°·s⁻¹，2999 是
   −0.046 / 3.6°·s⁻¹）。这是**一处实质退化且处在阈值临界**，按「判决不能取自被测量 / 双轴」
   的规矩，必须记为待解决项，而不是用 vx 涨幅盖过去。
3. ⚠️ **`tracks_half_command` 两者都 FAIL**（vx 只有命令 0.4 的一半）⇒ 已知的「训练命令上限
   设置」问题，**不是 7999 新引入**，也不是不稳；不要拿它当换点理由。
4. ✅ **跨 plant 专一性仍在**：7999 在 kp5 上 `terminated_frac=15.62%`、`no_fall` FAIL，
   与 2999 在 kp5 上 7/8 摔一致 ⇒ 续训没有让它变成「鲁棒策略」，部署仍必须逐颗把 reg50 配到 kp8。
5. ✅ **负对照能删红**：`model_5999` 当场 6 项门变红、term 79.69%。特别注意它的
   `error_vel_xy=0.1436` **比所有好策略都低**——单看这一项会得出「5999 最好」的反向结论。
   这正是项目里反复踩的「读数落在看似合理区间」：必须和 `no_fall`/`upright`/`dx` 一起读。

⇒ **落地建议**：维持现状（bundle 不动），把「7999 = 走路级但侧移门临界」写进部署边界；
下一次真要换点，按项目铁律做**外层 sweep 选点**（P3 任务，用户已拍板暂缓、~30 GPU 小时），
而不是用单次评测结果翻案。
