# 平地速度跟踪探索历程（2026-10-24 ~ 10-25）

目标：让 microduck 在**上游默认 flat 任务**（`Mjlab-Velocity-Flat-MicroDuck`）上按指令速度行走，
并且能**证明**它在走（不是微颤、不是滑行、不是原地打转）。

产物：`checkpoints/model_1250.pt`（iter 1250）、`evals/eval_iter1250_v2.json`（10/10 闸门）、
`evals/runmeta_vel_4096x12000_1025.json`（训练契约）。方法记录见 `docs/05-flat-walk.md`。

### 2026-10-25 09:20 iter 1250 首评：先抓到自己的评测 bug

第一次评估判出两条 FAIL：`translates_forward`、`not_sideways`。
「净位移 −0.039 m」看着像原地打转，但同一次运行的**体坐标** ∫vx·dt 是 **+1.6 m**——两个数不可能同时成立。

根因：`reset_base` 的 `pose_range["yaw"] = (-3.14, 3.14)`，各 env 初始朝向全圆周随机，
用世界系 `root_link_pos_w` 求净位移会互相抵消。
修法：投影到各 env **自己的初始朝向**，并把体坐标积分作为独立交叉校验。

修后：`dx_body = +1.575 m`（ratio 0.55）、`|dy_body| = 0.530 m`、10 项闸门全过。
**判据从「结果对不对」改成「两个独立来源是否互相矛盾」**——坐标系/单位/轴的量一律两条算法互校。

### 2026-10-25 09:45 里程碑守候上线

用**与 1250 完全同参**评测，写 `milestone_verdict.json`；两轮都「无改善」就自动停训（省约 5 h）。
判定阈值写在代码里可审计，并做了 6 例负对照（变好但闸门挂 → flat；速度涨但误差涨 → flat）。

## 2. 判决

**配方不动。** 1250 轮、`error_vel_xy 0.194`、10/10 闸门，已经超过公开的 5000–6000 轮水平；
在好策略上按 issue #46 动奖励（`air_time` 前进门控 + track 侧向加权）风险大于收益。

**issue #46 三处改法**仍写成了可回滚补丁 `tools/flat_walk/patch_issue46.py`
（`--check/--apply/--revert`，幂等、带备份、复用上游 `_forward_progress_gate`），
但**当前刻意保持 `NOT applied`**，只作为换任务时的待用件。

## 3. 留给下一个人的三句话

1. **先测参照，再看结果**：没有出厂 0.164 / Datawhale 0.4167 这两个数，你无法判断 0.25 是好是坏。
2. **任何坐标系转换，必须两条独立算法互校**；静默 bug 的输出总是落在「看起来合理」的区间里。
3. **上游 cfg 的字节哈希要进 runmeta**：`cfg_byte_identical_to_upstream: true` 是「我没偷偷改奖励」
   唯一的机器可验证证据。
